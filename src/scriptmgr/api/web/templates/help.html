Overview

ScriptManager is a local orchestration service running on your workstation. It lets you register, schedule, chain, and monitor scripts written in any language — all from a web browser.

ComponentWhat it does
Web UIThis browser interface — manage everything at http://localhost:8765
REST APIJSON API at http://localhost:8765/api — for automation or integration
SchedulerFires scripts on cron, interval, or continuous schedules automatically
RunnerLaunches your scripts as child processes, captures all output
DatabaseSQLite at data\scriptmgr.db — stores all config and run history
Windows ServiceKeeps everything running after reboot (set up via install-service.ps1)

Quick Start — 5 Steps

1 Go to Groups → click + New Group → enter a name (e.g. "AI Workflows") → Create
2 Go to Scripts → click + Add Script → fill in name, path, and select your group → Add Script
3 Click ▶ Run on your script — optionally add runtime parameters in the dialog → Run Now
4 You're taken to the Run detail page — watch live output as the script executes
5 (Optional) Go to Schedules to set it running automatically on a timer

1. Groups

Groups are folders that organise your scripts. Every script must belong to a group.

Creating a group

  1. Click Groups in the left sidebar
  2. Click + New Group
  3. Enter a Name (required) and optional description
  4. Click Create

Example groups

  • AI Workflows
  • Data Pipelines
  • Maintenance & Cleanup
  • Reports
  • DevOps
⚠ Deleting a group also deletes all scripts inside it and their run history.

2. Adding Scripts

A "script" is any executable file on disk — Python, PowerShell, Batch, Go, or a compiled binary.

Fields

FieldRequiredDescription
NameYesDisplay name — e.g. "Daily Report"
GroupYesWhich folder this script belongs to
Script / Executable pathYesFull path on disk — e.g. C:\scripts\report.py
Language / TypeNoLeave as Auto-detect — picks up from file extension. Override only if needed.
Default argsNoArguments always passed to the script. Supports quoted values: --env prod "my folder"
TimeoutNoKill script after N seconds. 0 = no limit.
DescriptionNoNotes shown in the scripts list

Path tips

  • Use the full absolute path: C:\Users\you\scripts\myscript.py
  • UNC paths work too: \\server\share\scripts\tool.exe
  • The script does not need to be inside the ScriptManager folder

3. Supported Languages & Auto-Detection

ScriptManager detects the right way to run your script from its file extension. You never need to type python or powershell manually.

Overriding the language

Use the Language / Type dropdown when adding a script to force a specific runner. For example, select Python to use a specific virtual environment's Python instead of the system default.

✓ You only need to enter the script name and path — ScriptManager handles the rest.

4. Running Scripts

Manual run

  1. Go to Scripts
  2. Click ▶ Run next to a script
  3. A dialog appears — optionally enter runtime parameters (extra args for this run only)
  4. Click Run Now — you're taken to the live log view

Runtime parameters

Parameters entered in the run dialog are appended to the script's default args:

Default args: --env prod
Runtime params: --output C:\results --date 2026-06-01
Final command: python script.py --env prod --output C:\results --date 2026-06-01

Use quotes for values with spaces: --folder "My Documents\Reports"

Run modes

ModeHow to use
One-shotClick ▶ Run — runs once and stops
ScheduledAdd a schedule (cron or interval) — runs automatically
Continuous re-runAdd a schedule with type continuous — re-runs automatically after finishing
Always-on serviceUse install-service.ps1 to wrap the whole server (or individual scripts) as Windows Services

5. Schedules

Schedules make scripts run automatically without any manual action.

Creating a schedule

  1. Go to Schedules → click + New Schedule
  2. Pick a Trigger Type and enter the Expression
  3. Select either a Script or Workflow to run
  4. Click Create

Trigger types & expressions

TypeExpression formatExampleMeaning
cron5-field cron0 * * * *Every hour on the hour
cron5-field cron0 9 * * 1-59am Mon-Fri
cron5-field cron*/15 * * * *Every 15 minutes
intervalSeconds300Every 5 minutes
intervalSeconds3600Every hour
continuousSeconds (delay after finish)10Re-run 10s after completing
dateISO datetime2026-12-31T23:59:00Run once at exact time

Managing schedules

  • Click ✓ On / ✗ Off to pause/resume a schedule without deleting it
  • Click Delete to remove it permanently

6. Workflows (Chaining Scripts)

Workflows let you chain multiple scripts together into a pipeline (DAG — Directed Acyclic Graph).

Creating a workflow

  1. Go to Workflows → click + New Workflow
  2. Enter a name and select a group → Create
  3. Use the REST API to add nodes (scripts) and edges (connections) to the DAG

DAG structure

Script A → Script B → Script C    (sequential)
Script A → Script B                (parallel fan-out)
        → Script C
Script B + Script C → Script D   (join / merge)

Edge conditions

ConditionMeaning
successOnly proceed if the previous script exited with code 0
failureOnly proceed if the previous script failed
alwaysAlways proceed regardless of exit code

Workflows can also be scheduled — add a schedule and target the workflow instead of a single script.

7. Viewing Run History & Logs

Run list

Go to Runs to see the last 100 runs across all scripts and workflows.

Run detail page

Click Logs on any run to see:

  • Status, start time, duration, exit code
  • Any runtime parameters that were passed
  • Full stdout and stderr output (stderr shown in red)

StatusMeaning

8. Windows Service (Auto-start on Boot)

ScriptManager is installed as a Windows Service called ScriptManager so it starts automatically when Windows boots.

Service management

ActionPowerShell commandGUI alternative
Check statusGet-Service ScriptManagerOpen services.msc
StopStop-Service ScriptManagerRight-click → Stop
StartStart-Service ScriptManagerRight-click → Start
RestartRestart-Service ScriptManagerRight-click → Restart

Service logs

The service writes all output to:

  • d:\repos\Test\data\logs\service-stdout.log — normal output
  • d:\repos\Test\data\logs\service-stderr.log — errors

Re-installing the service

If you move the repo or update Python, run this in an Administrator PowerShell:

cd d:\repos\Test
.\install-service.ps1

9. REST API

ScriptManager has a full JSON REST API. All UI features are available via API too — useful for integrations, CI/CD pipelines, or calling from other scripts.

Interactive API docs

Open http://localhost:8765/api/docs — this is Swagger UI where you can explore and call every endpoint directly from the browser.

Key endpoints

MethodEndpointAction
GET/api/scriptsList all scripts
POST/api/scriptsAdd a new script
POST/api/scripts/{id}/runRun a script (with optional params)
GET/api/runsList runs
GET/api/runs/{id}/logsGet log lines for a run
GET/api/groupsList groups
POST/api/schedulesCreate a schedule
GET/api/workflowsList workflows

Calling from another script

# Python example — trigger a script run via API
import requests
r = requests.post("http://localhost:8765/api/scripts/1/run",
    json={"params": ["--date", "2026-06-01"]})
print(r.json()) # {"run_id": 42}

10. Troubleshooting

ProblemFix
Site won't load at localhost:8765Run Start-Service ScriptManager or manually: d:\repos\Test\.venv\Scripts\scriptmgr.exe serve
Script shows "failed" with exit code 1Click Logs on the run — check stderr (red lines) for the actual error message
PowerShell script blockedThe runner uses -ExecutionPolicy Bypass automatically — if still blocked check your script path is correct
Script not found errorVerify the full path in the script settings. Use an absolute path, not relative.
Schedule not firingCheck the schedule is toggled On. Verify cron expression at crontab.guru
Port 8765 already in useAnother instance is running. Run Stop-Service ScriptManager then start again.
Service won't start after rebootCheck data\logs\service-stderr.log for errors. Re-run install-service.ps1 as Administrator.
Database errorsRun d:\repos\Test\.venv\Scripts\scriptmgr.exe db init to re-initialise

Log files

  • Service output: d:\repos\Test\data\logs\service-stdout.log
  • Service errors: d:\repos\Test\data\logs\service-stderr.log
  • Run logs: stored in the database, viewable on each run's detail page
